# 便携版

将压缩包完整解压到自己的可写文件夹，再运行程序。不要直接在压缩包或只读磁盘映像内启动。

- Windows 运行 `115+.exe`，保留同目录的 `runtime` 和 `data`。内置 WebView2 不安装到系统，也不下载其他运行库。Windows 10 启动时仅为这个 `runtime` 文件夹设置运行库所需的读取权限，不需要管理员权限。
- macOS 将整个文件夹移到自己可写的位置后打开 `.app`。`data` 位于 `.app` 旁边，不放进应用包内部。系统隔离运行可能使刚下载的应用处于只读位置，此时程序会提示移动文件夹。
- Linux 运行 AppImage；`data` 位于 AppImage 旁边。系统仍需满足 AppImage 本身的运行条件。

`data` 保存登录凭证、设置、上传/下载任务数据库、应用日志与缓存。macOS 的系统 WebKit 仍可能在系统管理的位置保存浏览器缓存。

首次运行不会自动读取已安装版本的账户。扫码登录后，凭证只保存到便携目录。不要把带有个人 `data` 的文件夹上传到 GitHub 或分享给其他人。

更新前退出程序，解压新版本并替换程序文件及 Windows 的 `runtime`，保留原来的 `data`。应用内“下载更新”仅打开发布页，不运行安装器、不覆盖数据。搬移文件夹前也请先退出程序；搬移后原有任务中的绝对文件路径不会自动改写。

关闭便携版主窗口会退出程序，有传输任务时沿用现有的退出确认与暂停流程，不强制隐藏到托盘。

如果 `data` 不可写或 Windows 的内置运行库不完整，程序会提示并停止，不会改用系统应用数据目录或临时安装其他运行库。

## 验证范围

RC.3 的同一个 Windows ZIP 已在 Windows Server 2022 和 2025 的 CI 环境通过以下原生运行验证：中文与空格路径、从其他工作目录启动、随包 WebView2、数据与测试凭证持久化、禁用安装更新器、下载暂停续传及 SHA1 校验、上传哈希与模拟秒传、关闭退出、移动整个文件夹后恢复设置与任务。

前端 11 项检查、Rust 普通模式 26 项及便携模式测试均通过；便携模式 Windows 32 项、macOS/Linux 33 项。Windows EXE 已检查不依赖额外的 VC++ 运行库，macOS 两种架构通过应用签名完整性检查，Linux 已完成构建。

这些测试未使用真实 115 账号，不覆盖真实扫码登录、云端 OSS 上传，也不能代替 Windows 10/11 普通用户桌面的完整验收。CI 调试配置仅用于一次性测试机，不随便携包分发。
